New project setup:
- Copy from the previous project: `tools/` (`scale-laptop.py`, `build-css.mjs`, `build-js.mjs`, `optimize-images.mjs`, `lighthouse.sh`, `lh-summary.mjs`), `package.json` (scripts + pinned devDependencies) and `.gitignore`. Then `npm install`.
- Adjust in the copies: CSS/JS source lists, browser `targets` in `build-css.mjs`, the originals path (`IMAGES_SRC`), and `tools/images.config.json` (starts empty: widths are measured per image).
- Check that Chrome DevTools MCP is connected (`claude mcp list`) before relying on browser checks.

Hard rules:
- Source CSS: desktop styles → `style.css`, all responsive overrides → `media.css`, vendor CSS in `css/vendor/`. No per-page CSS files.
- Source JS: only `js/main.js` (vanilla JS, no jQuery). Every feature is an `initX()` that returns early if its elements are missing, so one file serves all pages. Hook into markup with `data-*` attributes, not with styling classes.
- **The page links only the bundles** (`css/site.min.css`, `js/site.min.js`). After editing any source run `npm run build`. Never edit a generated file; every generated file starts with a "Generated by … Do not edit" banner.
- Vendor libraries are local files in `*/vendor/`, pinned to an exact version, never loaded from a CDN. New npm packages: pinned exact (`--save-exact`), and at least two weeks old.
- Header, footer and any announcement bar have identical markup on every page. Change one, change them all.
- Reuse existing components, tokens and assets before adding new ones. Before saving a Figma export, check for duplicate images by md5 (`md5 -q file`).
- Colours, gradients, radii, container width, easing and fonts are CSS custom properties on `:root`. No magic hex values in components.
- Inline `<script>` is allowed only in `<head>` for things that must happen before the first paint (e.g. `--fixed-vh`, an animation "pending" class). Keep each to one line and explain it in a comment.
- Never commit unless the user asks.

## Figma

- File: "<FIGMA FILE NAME>", key `<FIGMA_FILE_KEY>`. Frames: desktop `<node>` (<w×h>), mobile `<node>` (<w×h>), tablet `<node or "none">`. If the file gets copied, node ids stay the same; record the old keys here.
- Figma MCP is the source of truth. Workflow per frame:
  1. `get_metadata` on the frame → section list and positions.
  2. `get_design_context` (screenshot on). For a big flat frame, `forceCode: true` on the whole frame works; otherwise per section.
  3. `get_screenshot` at 1:1 (`maxDimension` = frame height) and slice it to compare section by section.
  4. Build → measure in the browser → compare to the Figma positions.
- Treat the generated code as a reference only. Use the project's tokens and components.
- **Flat frames** (no section groups): derive the section boundaries from the layers (backgrounds, image tops), write them down as a section map in this file (`Figma y → section, height`), and position children section-relative (`top = figmaY − sectionTop`).
- **Hidden and covered layers:** skip layers that are hidden, or fully covered by a later opaque layer. List them under "Deviations from Figma".
- **Rotated layers:** `get_metadata` x/y of a rotated node is NOT its bounding box; the generated code's wrappers are. Recreate a rotated element as one element centred on the bbox centre with `transform: rotate()`.
- **Masks on rotated layers:** the MCP's `mask-size` is the mask's bounding box, but the mask PNG is the unrotated shape (PNG size ÷ 2). Solve the unrotated window from the bbox: `W = (BW·cos − BH·sin) / (cos² − sin²)`, `H = (BH·cos − BW·sin) / (cos² − sin²)`, centred on the bbox centre. Then build the "card + window + photo" as one rotated element with an `overflow:hidden` window. Check that W×H matches PNG/2.
- **Opaque rectangular masks** (photo crops) are equivalent to an `overflow:hidden` box with the image offset inside. Check the mask alpha before choosing.
- Download MCP assets with curl, **including the file extension** in the URL (asset URLs expire after 7 days). Strip `preserveAspectRatio="none" overflow="visible" style="display: block;"` from SVGs, except where an SVG must stretch (e.g. a full-width curve), and say so in a comment. Remove the preview background rects from exported logos.
- Figma sometimes clips text with fixed-height frames, stretches images, has typos, inconsistent spacing, copy-pasted labels or duplicated numbering between frames. Don't copy those bugs. Show the full text, keep images undistorted, and tell the user about every deviation.
- **Text wrapping:** where Figma breaks lines differently from what its box width would give, it uses hard breaks. Reproduce them with hideable `<br class="…">`, not with tweaked widths. Measure text widths in the browser before choosing a box width.
- **Rendered vs box position:** occasionally Figma renders glyphs offset from the text box (mixed line-height spans). Match the rendered position, and note it.
- Missing content (draft copy, placeholder contacts, missing links) goes in "Content flagged to the client".

## Typography

- Font: <family, weights>. Licence: <who holds the web licence>. Without a web licence, use the system font via `local()` and flag it; never download fonts from unofficial sources.
- **Match Figma's vertical metrics:** Chrome draws Helvetica-like fonts ~0.1em lower than Figma. Wrap the font in `@font-face` with `ascent-override`/`descent-override`, solved so that the cap top sits at the text-box top. Verify on ~10 text blocks by finding the first white/ink pixel row in Figma vs the browser screenshot (within 1px). The overrides are % of font-size, so they work for any file of the family. Safari ignores them.
- **Self-hosted webfonts:**
  - WOFF2 only; `font-display: swap`; preload only the weight of the LCP text.
  - Subset to Latin (`fontTools.subset`, Google "latin" ranges, `--layout-features='*'`, keep hinting). Check coverage of every character the page can show, incl. `text-transform: uppercase` and JS messages.
  - Keep the originals outside the project.
  - Add a second `@font-face` family with `local()` and the same overrides as the fallback while loading, so the swap moves nothing on devices that have the font.
- **Check supplied font files** (fontTools): family/style names, weight class, units per em, vertical metrics, licence/copyright fields, glyph count. Then compare text widths against the reference font in the browser (per weight, min–max ratio). Files from mixed editions are common; flag any weight that is off by more than ~0.5%.

## Breakpoints (`css/media.css`)

| Range | Approach |
|---|---|
| ≥1920px | Desktop, exact Figma values (`style.css`) |
| 1280–1919px | Laptop: every px value × 0.75, `--container: 1440px`. **Generated**, see below |
| ≤1279px | Compact (tablet + mobile): the mobile Figma frame × `--m` (e.g. 1.35) |
| ≤768px | `--m: 1.2` |
| ≤480px | `--m: 1` — exact mobile Figma |
| ≤359px | `--m: <320/360>` — narrow phones |

- Order of work per page: 1920 → laptop ×0.75 → mobile frame → tablet (from the tablet frame if it exists, otherwise from the mobile frame scaled).
- No `transform: scale()`, `zoom` or vw-based layout sizing. Scale factors are CSS custom-property multipliers (`calc(Npx * var(--m))`).
- In `media.css`, the shared blocks for each breakpoint come first, page-specific blocks after. Label every block with a comment.
- **Laptop ×0.75 is generated** (`tools/scale-laptop.py`): it copies every declaration with px values from `style.css` × 0.75, keeps 1px hairlines and borders, and replaces only the block between `/* laptop:generated:start */` and `/* laptop:generated:end */`. Hand-written laptop overrides go after the end marker: images sized only by HTML `width`/`height`, and 1px lines that must stay on whole pixels. Never edit inside the markers.
- **Horizontal anchors** (so layouts survive viewports narrower than the scaled frame, e.g. 1280 < 1440):
  - Left half → `left: figmaX`.
  - Right half → `right: frameW − figmaX − w`.
  - Centred → `left: calc(50% ± …)`; its container needs `left:0; right:0`.
  - Elements that must stay next to each other (e.g. cards and the photos beside them) use the same anchor.
  - Full-bleed decorative layers align to the design frame with `left: calc(50% − var(--container) / 2)`.
- **Compact layout from the mobile frame:**
  - Every value is the Figma mobile value written as `calc(Npx * var(--m))`. Horizontal positions are offsets from the centre (`calc(50% ± N * var(--m))`, N = figmaX − frameW/2), so content forms a centred column of `frameW × m` with full-bleed backgrounds.
  - Full-screen blocks (hero) anchor their text to the screen edges instead.
  - Collages can spread wider than the column with a separate factor (`--spread`).
  - Buttons and form fields keep their own (unscaled) size; only their placement scales.
  - Write the block as a template with `m(N)` / `c(N)` macros and expand it with a script; it avoids hundreds of hand-typed `calc()`s.
- Sections with decor wider than the viewport: `overflow-x: clip` (not `hidden`, which would also clip anything poking out vertically).
- A `<br>` that gets hidden on smaller screens must have a space before it in the HTML (`text <br>more`). Design-only breaks: `<br class="br-design">` (hidden below desktop) / `<br class="br-compact">` (hidden on desktop).
- **Hero = one screen:** `height: var(--fixed-vh)`, set in `<head>` from `innerHeight`, and updated in JS only when the width changes (mobile toolbars must not make it jump). Pin the title to the top and the bottom elements to the bottom with Figma's distances; add a `min-height` so they never collide on short screens.
- Before a page has its real tablet or mobile design, it may rely on "Interim fixes" blocks that only stop horizontal overflow. Delete them when the real design lands.

## Components and patterns

Document each shared component here when you create it: class names, modifiers, `data-*` hooks, the `init` function, and the Figma node id.

- **Icons:** SVG masks, `<span class="icon icon--name" aria-hidden="true">`. They take their colour from `currentColor` and their size from `--icon-size`. One SVG file per icon in `assets/icons/`.
- **Buttons:** `.btn` plus modifiers (`--primary/--outline/--white/--ghost`, sizes `--md/--lg/--xl`). Colours via custom properties (`--btn-color`, `--btn-fill`, `--btn-hover-fg`). Per-instance width and padding come from a layout class, never from a new button class.
- **Hovers:** short transitions (0.3–0.55s, one easing token).
  - Fill effects use a `::before` layer (e.g. `clip-path: circle()` growing from the icon). The element's own background moves to an `::after` layer that fades out after the fill, to avoid an anti-aliased rim.
  - Never put a hover transition on an element that also carries a scroll-animation attribute (see Animations).
- **Forms:** `novalidate`, each field in a `.field-wrap` (positioning + animation target).
  - Rules in one `VALIDATORS` map picked by `data-validate`.
  - Error text inside the field (`aria-describedby`, `aria-invalid`), shown on blur when something was typed and on submit; it clears live while fixing. Focus goes to the first invalid field.
  - Success state in a `role="status"` line.
  - Without a backend, say so in the code and in "Content flagged".
- **Custom dropdown:** `[data-dropdown]` root, a toggle with `aria-expanded`/`aria-controls`, and a `role="listbox"` menu with `role="option"` items. The value lives in the root's `data-value`, and the component fires `change` on the root. It closes on outside click and on Esc, and supports arrow keys.
- **Mobile menu / drawers:** a toggle with `aria-expanded`, a backdrop, and Esc to close. Lock page scroll while open (and stop smooth scroll, if it's used).
- **Inner-page banner:** one shared hero class plus a per-page modifier. Per-page differences go through custom properties (e.g. `--hero-overlay`), not duplicated rules.
- **Page background patterns** (grid, texture):
  - Put them on **one wrapper** around everything between the banner and the footer, never per section. Sections inside stay transparent.
  - Spacing under the banner goes on `.hero + .wrapper` (padding-top), so the pattern starts right at the banner edge. Offset the pattern so it opens the way the design does.
  - A gradient that spans two sections: give both the same `background-size` and offset `background-position`.
- **Gradient text:** `background-clip: text` + `color: transparent`. No transforms on its children: a transformed child can drop out of the clip.
- **Dismissible bars and notices:** remember "closed" in `sessionStorage`, not `localStorage`.
- **Cart and other state:** frontend only, exposed as one global (`window.<Project>Cart`). Keep it to the current page's DOM.

## Animations and smooth scroll (if used)

- **Scroll animations (e.g. AOS):** set the attributes in `main.js` from one `ANIMATIONS` list (selector, effect, delay, stagger, duration, offset), not in the HTML. Re-run refresh after showing, hiding or reordering content (and on `load`). Nothing inside tabs or sliders animates. Respect `prefers-reduced-motion` (then set no attributes at all).
  - aos.css overrides `transition-property/duration/delay` of the animated element, so hover transitions go on its children or pseudo-elements.
  - AOS delays exist only in 50 ms steps; there is no `fade-in` (use `fade`).
  - Built-in AOS effects overwrite `transform`. For elements with their own transform (tilted cards), write custom effects with the individual `translate`/`scale`/`rotate` properties; they compose with `transform`.
  - The last items on the page need `offset: 0`, or they sit below the trigger line at max scroll. Clip the footer (`overflow:hidden`) so start offsets don't make the page taller.
- **Never animate the LCP element from `opacity: 0`** (Chrome ignores it for LCP). Set a "pending" class in `<head>` that holds it at `opacity: 0.01` until the animation takes over. Add fallbacks: remove the class if the library is missing; add a CSS animation that shows it after ~3 s.
- **Scroll-linked effects** (parallax, scrub, text fill) share one loop, `addScrollEffect({ measure, update })`:
  - `measure()` reads geometry in page coordinates only on init, resize, `load`, `fonts.ready` and a ResizeObserver.
  - `update(scrollY, vh)` only computes and writes; no layout reads per frame. Use `offsetTop` for elements that move themselves.
  - Run it inside the smooth-scroll library's tick (same frame), plus a rAF-throttled native `scroll` fallback.
  - Write styles only when they change; animate only compositor properties (`translate/scale/rotate/opacity`) with `will-change`.
- **Transforms create stacking contexts.** Any bar that holds a dropdown or popover gets `position: relative; z-index: <n>`.
- **Smooth scroll (e.g. Lenis):** use its own rAF loop if `autoRaf` is missing; keep native scroll in inner scroll areas (`data-lenis-prevent`); stop it while a drawer or modal is open; route in-page `#` links through `lenis.scrollTo` (with the sticky header's offset); don't start it with reduced motion.

## Images

- **Originals stay outside the project** (`../<project>-originals/images/`), never edited or served.
- `tools/optimize-images.mjs` (sharp) builds `assets/images/<name>-<width>.webp` (+ `.avif`) from `tools/images.config.json`:
  - Never upscale.
  - Quality is adaptive per variant, judged by PSNR against the original at the same width: WebP q90 → 94 → 97 → 100 until ≥ 42 dB; q100 is accepted at ≥ 40 dB, otherwise near-lossless.
  - AVIF (4:4:4) at the lowest quality reaching the WebP's PSNR (capped at ~44 dB); an image gets AVIF only if the whole set is smaller.
  - Call `sharp.cache(false)`, or re-encoded files are measured from cache.
- **Widths** = the CSS size each `<img>` actually needs at every breakpoint (cover crops included: `max(w, h × aspect)`) × 2, plus × 3 on phones, capped at the original. Measure them in the browser with iframes per breakpoint; don't guess.
- Markup: `srcset` with `w` descriptors and `sizes` with one entry per breakpoint (`100vw` for full-bleed). AVIF via `<picture><source type="image/avif" …><img …webp…></picture>` with `picture { display: contents }`; any `.x > *` rule also gets `.x > picture > img`.
- The LCP/hero image: eager, `fetchpriority="high"`. Everything else: `loading="lazy" decoding="async"`. CSS background textures: crop to the visible part (lossless).
- **Verify quality:** render the old page (original PNGs) and the new one at 2× and compare screenshots by PSNR per region (≥ 40 dB). Look at zoomed side-by-side crops. Make sure animation states match before blaming compression.

## Build and performance

- `npm run build` = `build:css` (laptop generator + lightningcss bundle) + `build:js` (vendor + esbuild-minified `main.js`).
  - lightningcss needs explicit `targets` (the oldest browsers the CSS already needs). Without them it drops `-webkit-backdrop-filter` (Safari < 18). After a build, check that prefix counts in the bundle equal the sources.
  - Scroll-animation CSS stays render-blocking (inside the bundle). Loading it late shows elements, then hides them for their entrance.
- **Lighthouse:** `npm run lh -- <name> [mobile|desktop]` (headless Chrome, JSON + HTML into `lighthouse/`), `npm run lh:summary -- a.json [b.json]`.
  - Mobile uses simulated throttling (Lantern): every request that starts before the observed LCP counts against the LCP. Fewer early bytes (smaller images, subset fonts) is what moves it; preloads and priority tweaks usually don't.
  - Simulated LCP varies ±1.5 s between identical runs: compare **medians of 3 runs**, and A/B a change by toggling only that change.
  - `python3 -m http.server` sends no `Cache-Control`; caching is a hosting setting (write the rules for the actual host).
- Keep a "tried and rejected" list here, with numbers, so nobody repeats it.

## Accessibility baseline

- Semantic landmarks (`header`, `nav`, `main`, `footer`) and one `h1` per page (repeated titles elsewhere are `p`).
- Every control is a real `<button>` or `<a>`.
- Icon-only buttons have an `aria-label`. Decorative icons and images have `aria-hidden="true"` or `alt=""`.
- Use `aria-expanded`/`aria-controls` on toggles and `aria-live="polite"` / `role="status"` on status text that changes.
- Focus states are visible (`:focus-visible`, also for hover-only effects). Everything works from the keyboard (Tab, Enter/Space, Esc, arrow keys in listboxes).

## How to verify (every change)

1. Run `python3 -m http.server 8765` in the project folder (Lighthouse runs stop it; restart before browser checks). Stop it afterwards with `pkill -f "http.server 8765"`.
2. Rebuild first (`npm run build`), then reload with `ignoreCache`; stale files cause false alarms.
3. Positions: measure with `offsetLeft/offsetTop` chains (not affected by animation transforms) and compare to Figma, per breakpoint: 1920 exact, 1440 = ×0.75, 360 = mobile frame. Pin the hero height with an `initScript` setting `--fixed-vh` to the Figma height for exact comparisons.
4. Horizontal overflow (`scrollWidth > width`) and overlapping text boxes, at 1920, 1440, 1280, 1279, 1024, 960, 769, 768, 600, 480, 390, 360, 359 and 320px: sweep with iframes of each width. Also check real glyph extents (`Range.getClientRects`), ignoring elements that haven't animated in yet.
5. Refactors that must not change rendering (bundling, minifying, `<picture>` wrappers, font swaps): compare every computed property (or every element box/text width) between old and new in **sandboxed iframes without scripts** (deterministic, animation-free) at several widths. Exclude custom properties (only their text form changes).
6. Performance: `chrome-devtools` emulate with `viewport` **and** `cpuThrottlingRate` in the same call (a CPU-only call resets the viewport). Run a rAF `scrollTo(y += 30)` loop and record frame deltas plus `long-animation-frame` / `layout-shift` entries. A trace shows forced reflows as `UpdateLayoutTree`/`Layout` nested in `FunctionCall`.
7. Interactive parts: open dropdowns, menus and drawers, and use `document.elementFromPoint` at their centre to confirm they're on top. Test reduced motion and "library missing" by overriding `matchMedia` / `window.<Lib>` in an `initScript`.
8. Regression: page height and positions at the widths already designed stay the same; the console has no errors (a missing `favicon.ico` 404 is harmless; errors from your own sandboxed test iframes are expected).
9. Report deviations from Figma honestly, along with what was verified and what wasn't. Nothing is committed unless the user asks.
